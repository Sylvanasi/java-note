# 事务隔离级别：SQL 标准

![[附件/知识总览/01-事务隔离级别-SQL标准.svg]]

## 1. 隔离级别解决什么问题

多个事务同时访问数据时，一个事务能看到其他事务的哪些修改，以及并发执行能提供什么一致性保障，由事务隔离级别约束。

SQL 标准定义隔离保障；数据库通过多版本并发控制（MVCC）、锁等机制实现；Spring 提供事务配置入口，不负责实现数据库内部的隔离机制。

隔离增强不是逐级关闭查询、修改或删除，而是加强数据可见性与并发冲突的约束。

## 2. 三种并发现象

| 现象                         | 判断重点                                   | 示例                                      |
| -------------------------- | -------------------------------------- | --------------------------------------- |
| 脏读（Dirty Read）             | 读取发生时，读到其他事务尚未提交的修改           | 原余额为 100，其他事务改为 80 尚未提交，本事务就读到 80       |
| 不可重复读（Non-repeatable Read） | 同一事务重复读取已有数据，因其他事务已提交的修改而变化                | 第一次读到余额 100，其他事务修改并提交后，第二次读到 80         |
| 幻读（Phantom Read）           | 同一事务重复按相同条件查询，因其他事务提交的变更，符合条件的记录集合发生变化 | 第一次查询未读消息有 5 条，其他事务新增符合条件的消息并提交，再查询多出一条 |

**脏读看提交状态，不可重复读看同一行，幻读看符合条件的一批行。**

- 脏读按读取发生时判断。即使其他事务后来提交，提交之前读取其修改仍是脏读；不要求最终发生回滚。
- 事务读取自己尚未提交的修改是正常行为，不叫脏读。
- 幻读关注记录集合，不只是行数；数量相同，符合条件的记录也可能变化。修改条件字段使记录进入或离开查询范围，也可能改变集合。
- 上述不可重复读、幻读的例子关注其他事务造成的变化；自己写入后查询结果改变，不能直接据此判断出现并发异常。

## 3. 四种标准隔离级别

| 隔离级别（从弱到强）                | 脏读  | 不可重复读 | 幻读   |
| ------------------------- | --- | ----- | ---- |
| 读未提交（READ UNCOMMITTED，RU） | 允许  | 允许    | 允许   |
| 读已提交（READ COMMITTED，RC）   | 避免  | 允许    | 允许   |
| 可重复读（REPEATABLE READ，RR）  | 避免  | 避免    | 标准允许 |
| 串行化（SERIALIZABLE）         | 避免  | 避免    | 避免   |

## 4. 从名称推导保障

先记三种现象：**没提交、同一行、一批行。**

再记四个级别：**未提交也看 → 只看已提交 → 重读保持稳 → 效果如串行。**

1. 读未提交：允许看到别人未提交的修改，三种现象均无避免保证。
2. 读已提交：先挡住“没提交”，避免脏读；别人后来提交的新修改仍可能影响后续读取。
3. 可重复读：再保障“同一行”的重复读取，但标准仍允许符合条件的记录集合变化。
4. 串行化：提供等价串行执行的保障，三种现象均避免。

复习时先遮住隔离级别表，写出三种现象，再根据级别名称逐行推导；比单独背十二个格子更容易重建知识。


## 5. 标准保障与数据库实现的边界

“允许”表示该级别不保证避免，并非每次执行都会出现。具体数据库可以提供比标准最低要求更强的保障，不能直接把标准表当成某个数据库所有 SQL 场景的行为表。

串行化要求并发执行的效果等价于某种串行执行顺序，不代表数据库只能让所有事务一个接一个运行。三种现象的表格是经典记忆入口，不是对所有并发异常的完整枚举。

不能只看“没有脏读、不可重复读和幻读”就断言所有并发结果都可串行化；这张经典表不是全部异常清单。还要看写入之间的依赖及具体隔离实现。

例如 PostgreSQL 的 RR 可以比标准表提供更强的幻读保障；MySQL InnoDB 则还需区分快照读、锁定读和索引锁范围。不能把此标准表直接替代具体数据库的读写行为说明。

本次核对的是标准概念及数据库官方文档对标准的解释，没有运行并发 SQL 实验；实际行为需明确数据库版本、隔离配置、SQL 类型与提交时序后验证。

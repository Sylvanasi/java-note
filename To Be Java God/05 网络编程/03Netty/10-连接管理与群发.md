# 10｜连接管理与群发

## 1. ChannelGroup 是什么

ChannelGroup 是线程安全的 Channel 集合，支持对一组连接批量 write、flush、close。连接关闭后，DefaultChannelGroup 会自动移除它。

与 BIO 中自行维护在线连接 Map 的目标类似，但 Netty 已提供连接集合和批量操作机制。

## 2. 不要与 EventLoopGroup 混淆

| 对象 | 管理什么 |
|---|---|
| EventLoopGroup | 事件循环与线程 |
| ChannelGroup | 一组 Channel |
| ChannelPipeline | 一个 Channel 的 Handler 链 |

把连接加入 ChannelGroup，不会改变它所属的 EventLoop。

## 3. 定义共享的在线连接集合

```java
private static final ChannelGroup online =
        new DefaultChannelGroup(GlobalEventExecutor.INSTANCE);
```

当前每条连接都会创建 ChatHandler，用 static 让这些 Handler 实例共享同一个在线集合。如果各自拥有独立集合，就无法自然表示所有在线连接。

构造器中的执行器用于组操作结果的通知；实际连接 I/O 仍由各自的 EventLoop 执行。

## 4. 连接激活时加入

```java
@Override
public void channelActive(ChannelHandlerContext ctx) {
    online.add(ctx.channel());
    System.out.println("连接建立：" + ctx.channel().remoteAddress());
    ctx.fireChannelActive();
}
```

加入的是当前客户端对应的连接 Channel，不能把监听端口的 Channel 当成一个普通群聊接收者。

## 5. 连接断开时要不要移除

DefaultChannelGroup 会监听加入 Channel 的关闭，关闭后自动移除，因此当前用法无需自己再 remove。

```java
@Override
public void channelInactive(ChannelHandlerContext ctx) {
    System.out.println("连接断开：" + ctx.channel().remoteAddress());
    ctx.fireChannelInactive();
}
```

手动 `online.remove(ctx.channel())` 可以，但本场景是重复清理。自己维护普通 Map 时则要自己管理移除。

## 6. 单发与群发

```java
ctx.writeAndFlush(text);    // 当前连接
online.writeAndFlush(text); // 集合中符合发送条件的连接
```

本实验加入的都是普通连接 Channel，群发会包含发送者自己。

一个简化的业务处理示意：

```java
@Override
protected void channelRead0(ChannelHandlerContext ctx,
                            Models.ChatMessage msg) {
    if (msg.type() == 2) {
        ctx.writeAndFlush("PONG\n");
        return;
    }

    online.writeAndFlush(
            ctx.channel().remoteAddress() + "：" + msg.content() + "\n");
}
```

这里业务消息只提交一次群发。原代码中若残留两次 online.writeAndFlush，就会产生两份群发输出，这不是 TCP 自动重传造成的重复业务回调。

## 7. ChannelGroupFuture

```java
ChannelGroupFuture future = online.writeAndFlush(text);
```

单个连接的操作返回 ChannelFuture；一组连接的批量操作返回 ChannelGroupFuture。

组结果可反映全部成功、部分失败等状态；需要定位失败目标时，应检查各个 Channel 对应的结果。

重要区别：群发失败时，当前业务 Context 对应的是原发送者。直接 `ctx.close()` 关闭的是发送者，不一定是发送失败的目标接收者。

组写成功仍不表示每个接收方的业务已完成。真正的业务确认要有额外协议。

## 8. 为什么只写一个客户端类也能测试

同一个 NettyClient main 启动两个进程，就有两条独立连接：

```text
客户端进程 A：本地随机端口 A → 服务端 9094
客户端进程 B：本地随机端口 B → 服务端 9094
```

不需要复制一个 NettyClient2 类，也不需要更改目标服务端端口。

IDEA 的 Application 运行配置可在 Modify options 中启用 Allow multiple instances，再同时运行两份。

只发送 PING 不会产生业务群发。要验证广播，应发送 type=1 消息，并检查双方都能收到彼此的内容。

## 9. 换行数量也属于协议

如果请求内容自身末尾已经带换行，服务端再拼接一个换行，客户端按行读取时可能看到额外空行。

明确正文是否包含末尾换行，避免把显示层的空行误判成收到多条业务消息。

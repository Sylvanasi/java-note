# 动态代理

![[附件/知识总览/04-动态代理.svg]]

## 1. JDK 代理的对象与职责

- **目标对象 target**：真正执行业务，例如 MessageServiceImp。
- **代理对象 proxy**：JDK 在运行时生成的代理类的实例，实现指定接口，例如 MessageService。
- **调用处理器 InvocationHandler**：接收代理转交的方法调用，执行增强逻辑，并决定是否调用目标。

`new InvocationHandler() { ... }` 创建处理器对象并定义处理逻辑，不会立即执行 invoke 方法体。之后调用代理方法，才会进入处理器的 invoke。

## 2. JDK 调用链与执行时点

以下以目标方法正常返回为前提：

调用者调用代理的 send，代理转交 InvocationHandler.invoke；处理器先执行前置逻辑，再反射调用目标。目标正常返回后，处理器执行后置逻辑并把结果交回代理，最后返回调用者。具体步骤如下。

### 按调用顺序理解

1. 执行 `proxy.send("hello")`。proxy 实际指向实现了 MessageService 接口的 JDK 代理类实例。
2. 代理的 send 方法由 JDK 生成，负责将调用转交给处理器的 invoke，同时传入代理自身、描述 send 方法的 Method 对象，以及包含 "hello" 的参数数组。
3. 进入匿名内部类对象的 invoke 方法，先打印“打印日志前”。
4. 执行 `Object result = method.invoke(target, args)`。此时 method 已明确代表本次调用的 send 方法，通过反射在目标对象上执行该方法，并传入参数。
5. 目标对象执行 `send(String msg)`，msg 的值为 "hello"，因此打印 hello。这里是参数数组中的元素传给 msg，并非直接打印数组本身。
6. 目标方法执行结束。send 返回类型是 void，因此 Method.invoke 的返回值 result 为 null。
7. 回到处理器，打印“打印日志后”。
8. 处理器返回 result 给代理；对于 send 这样的 void 方法，代理不向调用者返回业务值，调用结束。

**第 3～8 步是处理器 invoke 方法的执行过程，不是 InvocationHandler 对象的创建过程。** 同一个代理连续被调用两次，通常使用同一个处理器对象，但 invoke 会执行两次。

## 3. 生成的代理类如何转交调用

下面是帮助理解的伪代码，省略了异常处理等细节。实际生成的类通常使用父类 Proxy 保存的处理器 h，而非重复声明 handler。

```java
class $Proxy0 extends Proxy implements MessageService {

    // 预先保存接口方法的描述信息
    private static final Method SEND_METHOD;
    private static final Method RECALL_METHOD;

    // 构造时把处理器交给父类保存；其他初始化省略
    public $Proxy0(InvocationHandler handler) {
        super(handler);
    }

    @Override
    public void send(String msg) {
        h.invoke(this, SEND_METHOD, new Object[]{msg});
    }

    // 假设接口还声明了 recall(String)
    @Override
    public void recall(String msg) {
        h.invoke(this, RECALL_METHOD, new Object[]{msg});
    }
}
```

代理方法统一转交给同一个处理器；处理器根据本次传入的 method 和 args 执行相应逻辑。

## 4. 处理器、返回值与异常语义

下面是理解转发与日志顺序的简化示例，异常透传等生产语义需另行处理。

```java
MessageService target = new MessageServiceImp();

MessageService proxy = (MessageService) Proxy.newProxyInstance(
        MessageService.class.getClassLoader(),
        new Class<?>[]{MessageService.class},
        new InvocationHandler() {
            @Override
            public Object invoke(Object proxy, Method method, Object[] args)
                    throws Throwable {
                System.out.println("打印日志前");
                Object result = method.invoke(target, args);
                System.out.println("打印日志后");
                return result;
            }
        }
);

proxy.send("hello");
```

- 目标调用由 method.invoke(target, args) 显式触发；删除这行，目标业务不会自动执行。
- send 返回 void，因此 return result 与 return null 在本次 send 调用中效果相同。
- 对于返回 String 等引用类型的方法，return null 会丢弃目标返回值。
- 对于返回 int 等基本类型的方法，处理器返回 null 会在代理转换返回值时触发 NullPointerException。
- 如果目标调用抛出异常，后面的“打印日志后”不会执行；需要无论成功失败都执行的清理逻辑应放入 finally。
- 在这个不设终止条件的通用处理器中执行 method.invoke(proxy, args)，会再次调用同一个代理并进入处理器，形成递归。应委托给 target。在 main 中通过反射调用代理本身则可以正常工作，只要处理器最终委托给目标。

Method.invoke 会把目标抛出的异常包装为 InvocationTargetException。若处理器直接将包装异常抛出，而接口又未声明该受检异常，JDK 代理可能进一步包装成 UndeclaredThrowableException。希望保持目标异常语义时，应按需求解包其 cause，并遵守接口异常约定。

无参方法传入的 args 可能为 null；基本类型返回值需要匹配包装类型，返回不兼容对象会引起类型转换问题。equals、hashCode、toString 也可能进入处理器，在 invoke 内直接打印 proxy 可能再次触发 toString，需防止意外递归。

## 5. CGLIB 创建与拦截

CGLIB 通过生成目标类的子类，并重写可拦截的方法，将调用转交给 MethodInterceptor。它不要求目标类实现接口；如果父类实现了接口，代理子类也属于该接口类型。

MessageServiceImp 实现 MessageService；CGLIB 生成的类继承 MessageServiceImp，因此也属于 MessageService 接口类型。

因此代理既可以用 MessageServiceImp 类型接收，也可以赋给 MessageService 接口变量。

### 创建与拦截

Spring 项目可使用 org.springframework.cglib.proxy 包中的 Enhancer、MethodInterceptor 和 MethodProxy；Method 来自 java.lang.reflect。

```java
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(MessageServiceImp.class);

enhancer.setCallback(new MethodInterceptor() {
    @Override
    public Object intercept(
            Object obj,
            Method method,
            Object[] args,
            MethodProxy methodProxy
    ) throws Throwable {
        System.out.println("调用前：" + method.getName());
        Object result = methodProxy.invokeSuper(obj, args);
        System.out.println("调用后：" + method.getName());
        return result;
    }
});

MessageServiceImp proxy = (MessageServiceImp) enhancer.create();
String result = proxy.recall("1");
System.out.println(result);
```

- setSuperclass：指定生成的代理类继承哪个类。
- setCallback：设置拦截器，此时只是保存处理逻辑。
- create：生成或复用代理类，并创建代理实例；上述无参调用要求存在可用的无参构造方法。
- obj：本次调用所在的代理对象。
- method：本次被拦截方法的描述信息。
- args：本次调用的参数。
- methodProxy：用于调用原实现等操作的辅助对象；invokeSuper 进入父类实现，避免重新进入当前重写方法。

假设 recall 返回 "recall" + messageId，正常调用的预期输出为：

| 顺序 | 正常路径的输出 |
|---|---|
| 1 | 调用前：recall |
| 2 | 调用后：recall |
| 3 | recall1 |

## 6. CGLIB 子类调用与 this

以下是帮助理解的伪代码，省略初始化、异常处理和回调绑定等细节，不是可直接编译的源码，辅助方法名称仅作示意：

```java
class MessageServiceImp$$CglibProxy extends MessageServiceImp {

    private MethodInterceptor interceptor;

    private static final Method RECALL_METHOD;
    private static final MethodProxy RECALL_METHOD_PROXY;

    @Override
    public String recall(String messageId) {
        Object result = interceptor.intercept(
                this,
                RECALL_METHOD,
                new Object[]{messageId},
                RECALL_METHOD_PROXY
        );
        return (String) result;
    }

    // invokeSuper 可通过类似这样的辅助入口调用父类实现
    final String recallSuper(String messageId) {
        return super.recall(messageId);
    }
}
```

invokeSuper 的效果可理解为进入辅助入口执行 super.recall，而不是再次执行 obj.recall。

### 调用流程

调用者调用代理子类的 recall，重写方法转交 MethodInterceptor；拦截器执行前置逻辑，使用 invokeSuper 进入父类原实现，得到 recall1 后执行后置逻辑，再把结果返回调用者。

**这个手写 CGLIB 示例没有另外创建 target。父类实现执行时，this 仍是代理对象。** 父类不是另一个对象，不能把继承关系理解成“代理对象内部装着一个父类对象”。

若父类方法内部通过 this 调用另一个可被拦截的重写方法，在此 invokeSuper 模型下可能再次进入拦截器。这与常规 Spring AOP 委托给独立 target 的模型不同。

## 7. 继承限制与代理适用边界

- final 类不能被继承，无法创建这种子类代理。
- final 方法不能被重写，无法通过子类重写拦截。
- private 方法不能被子类重写，不能按这种方式增强。
- static 方法不参与实例方法的多态重写。

JDK 代理不继承目标实现类，因此目标实现类中的 final 方法仍可经接口代理接收调用并增强。

## 8. JDK 与 CGLIB 对比

| 对比项 | JDK 动态代理 | CGLIB 动态代理 |
| --- | --- | --- |
| 生成类的关系 | 继承 Proxy，实现指定接口 | 继承目标类 |
| 是否要求业务接口 | 要提供用于暴露业务方法的接口 | 不要求 |
| 回调 | InvocationHandler.invoke | MethodInterceptor.intercept |
| 接收代理的业务类型 | 接口类型 | 目标类或其接口类型 |
| 本文示例执行原业务的方式 | method.invoke(target, args) | methodProxy.invokeSuper(obj, args) |

JDK 的接口数组只能传接口 Class；传入 MessageServiceImp.class 会抛 IllegalArgumentException，而不会切换成子类代理。JDK 代理类与 MessageServiceImp 没有继承关系，不能将其强转为该实现类。



Spring AOP 的实际代理选择还受配置影响，不能只凭“目标实现了接口”认定一定使用 JDK 代理。本文的手写 CGLIB invokeSuper 示例也不能代替 Spring 的独立 target 委托模型；理解自调用时必须先确认实际调用落在哪个对象上。

本次对照 JDK 反射代理与 Spring/CGLIB 文档核对，并查看项目 MessageServiceImp 中的手写 invokeSuper 示例；未重跑异常包装、递归或代理限制实验。

### 会议场景/线程池
· 改造**会议通知功能**：单场会议参会人可达上百人，统一平台只提供单条推送代办，串行推送效率低，改为线程池并发下发通知（有界队列 + 拒绝策略 + 单条失败隔离重试），替代原串行逐个推送

```
    public AtomicInteger rejectedCount() {

    }

    }

public ThreadPoolExecutor createPool(int core, int max, int capacity, AtomicInteger rejected) {  
    AtomicInteger seq=new AtomicInteger();  
    ThreadPoolExecutor pool = new ThreadPoolExecutor(core, max, 30, TimeUnit.SECONDS,  
            new ArrayBlockingQueue<>(capacity),  
            (r) -> new Thread(r, "meeting-notify-" + seq.getAndIncrement()),  
            (task,excutor) -> {  
                rejected.incrementAndGet();  
                throw  new RejectedExecutionException("会议通知队列已满");  
            });  
    return pool;  
}
```

Q:
1.你把上百人的会议通知从串行改成线程池并发：**核心线程数、最大线程数、队列和拒绝策略分别怎么设置？为什么？**

我采用固定大小的线程池，核心线程数和最大线程数都设为 10，限制同时发送通知的数量，避免下游接口压力过大。使用容量为 500 的有界队列，参数结合接口耗时、峰值任务量和压测调整。拒绝策略使用 AbortPolicy，在提交处捕获拒绝异常，将未提交成功的通知持久化；任务执行中的发送失败另外捕获并记录。之后由定时任务有限重试，通过通知业务唯一键防止重复发送。

Q:
1.过滤器发现用户未登录，跳转 IDaaS 前，你的 `state` 是怎么生成、保存的？回调时又怎么校验？
state存在时效性 ,并且缓存在用户的session中,其他人拿到链接没办法通过这个链接走完后续的流程
2.state 已经校验通过，为什么还要让授权码 code 一次性消费？它们防的是同一个问题吗？
state 用来关联当前浏览器发起的登录请求和回调，主要防登录 CSRF。code 是后端兑换 token 的临时凭证，由 IDaaS 保证短期有效、只能成功兑换一次，防止重复兑换。两者用途不同，不能互相替代。
3.OA 后端用 code 换到 token 后，为什么还要做“IDaaS 账号 → OA 本地账号”的映射，不能直接拿 token 当作 OA 已登录吗？
token是用户凭证不是用户信息,token 用于向 IDaaS 获取用户身份，但 IDaaS 身份不等于 OA 本地账号和权限
4.IDaaS 认证成功，但映射不到 OA 本地账号，你会怎么处理？
跳转至创建用户界面,用户创建成功创建映射关系
5.你说“回调地址走白名单校验”，这个回调地址由谁校验？为什么不能允许随便填写一个地址？
IDaaS 校验 redirect_uri，保证授权码只回到登记的 OA 回调接口；OA 登录后跳转到哪个页面，也不能绕过后端权限校验。

### 康佳合同流程

1. **合同进来之前**：非格式合同先在系统里走**预审**——业务、财务、法务来回改文本，每改一版留痕，可以版本比对；定稿后申报时直接引用，一个预审稿只能被一个合同用。
2. **合同申报**：填相对方、标的物、结算计划（首期款/阶段款/尾款）；要不要预算控制由经办人勾，勾了就从共享把事前申请单和招标结果带过来；需要交履约保证金的，在申报单上按相对方录保证金。
3. **合同审批与签订**：走 OA 流程，中间驳回、作废都有对应处理。
4. **状态对账**：合同一提报就把「新增」推给财务共享，之后驳回、废弃、归档（共享侧转"确认"）、变更、终止都实时同步；另外一套同步给 SAP。
5. **归档后进入履约**：合同条款拆成履约计划，每个阶段可以多次验收，验收要传证明材料，进度同步给共享——共享付款时拿这个做结算控制。
6. **钱怎么对**：保证金收（可以多次认领）、退、扣三条线，没收齐保证金不允许履约；共享把**收付款记录和发票记录回传**到合同系统，形成两张台账。
7. **人有风险怎么办**：法务发起**冻结相对方**，同时锁定它在途的合同；解冻是一次性全恢复，再同步给共享、MDM 和 SAP。
8. **底座**：所有跨系统的推送都走一个**异步定时任务队列**，带执行次数、最后请求/响应，支持失败重试和延迟执行。
